> 基于 DeepSeek + Dify 智能体开发实训项目
> 版本 V1.0 · 2026-07-08

---

## 一、总体思路与展示形态

- **形态定位**：纯 H5 移动端页面，以 **375×812**（iPhone 参考尺寸）为设计基线，`viewport` 缩放到设备真实宽度。
- **在网页里展现**：桌面端访问时，在浏览器中央放置一个 **手机外壳容器**（宽 375、高 812、圆角 + 阴影 + 状态栏），页面内容在这个容器内滚动；移动端访问时，容器自动铺满全屏。
- **一套代码适配**：通过 `@media (min-width: 768px)` 判断显示外壳；`rem/vw` 做移动端内部布局适配。
- **技术栈固定为原生三件套**：HTML5 + CSS3 + 原生 JS（ES6+），符合需求规格与实训要求，不引入框架。可选轻量库：Font Awesome 6、ECharts（图表）、Swiper（首页轮播）、Marked（AI 回复的 Markdown 渲染）。

## 三、移动端「网页外壳」样式方案

```css
/* PC 端显示为居中的手机 */
@media (min-width: 768px) {
  body {
    display: flex;
    justify-content: center;
    align-items: center;
    min-height: 100vh;
    background: #e6ebf1;
  }
  .phone-frame {
    width: 375px;
    height: 812px;
    border-radius: 36px;
    box-shadow: 0 20px 60px rgba(0, 0, 0, .25);
    overflow: hidden;
    position: relative;
    background: #fff;
  }
  .phone-frame::before {
    /* 顶部刘海 */
    content: '';
    position: absolute;
    top: 0;
    left: 50%;
    transform: translateX(-50%);
    width: 150px;
    height: 24px;
    background: #111;
    border-radius: 0 0 18px 18px;
    z-index: 10;
  }
}

/* 移动端全屏 */
@media (max-width: 767px) {
  .phone-frame {
    width: 100vw;
    height: 100vh;
    border-radius: 0;
  }
}
```

所有页面根节点统一使用 `.phone-frame`；`meta viewport`：`width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no`。

## 四、信息架构与路由（9 大功能）

底部 **TabBar 5 项**（移动端典型）：**首页 · 生活方案 · AI 助手（凸起大按钮）· 打卡 · 我的**
其余功能（风险预测、资讯、咨询、糖尿病类型）从首页宫格入口进入。

| 一级入口 | 页面 | 关键交互 |
|---|---|---|
| 首页 index | Banner 轮播、功能宫格（8 项）、健康资讯 3 条、糖尿病类型入口 | 上拉刷新、点击进入子页 |
| 风险预测 risk | 分步表单（基本信息 → 生理指标 → 生活习惯） | 步骤条、BMI 自动计算 |
| 风险报告 risk-report | 环形风险图 + 因素标签 + 建议 | 一键去咨询 / 生成方案 |
| 生活方案 plan | 顶部健康目标卡；「今日饮食」「今日运动」卡片；重新生成 | 计划完成时可打卡 |
| 医生列表 consult-list | 医生头像/科室/职称卡列表 | 点击进入对话（携带 chat_token） |
| 名医对话 consult-chat | 微信风气泡 + 输入框 + 图片上传 | 调 Dify Chatflow |
| AI 助手 assistant | 欢迎语、快捷问题 Chips、连续多轮对话 | 引用来源标签、Markdown 渲染 |
| 打卡 checkin | 顶部日历 + 类型 Tab（饮食/运动/血糖/用药/体重）+ 表单 | 提交后动画反馈 |
| 打卡分析 checkin-analysis | 7/30 天血糖/体重折线图 + AI 状态分析 | 调打卡分析工作流 |
| 资讯 news | 分类 Tab + 卡片列表 | 支持收藏 |
| 资讯详情 news-detail | 正文 + 收藏 + 分享 | 阅读量 +1 |
| 糖尿病类型 diabetes-type | 4 种类型卡片 → 详情（发病机制/表现/治疗） | 纯知识展示 |
| 个人中心 profile | 头像/昵称、健康档案摘要、历史记录入口、退出登录 | 各子页跳转 |
| 登录/注册 login/register | 手机号/账号 + 密码 + 验证码 | Token 存 localStorage.user |

## 五、数据交互层（对接 Dify + Express+SQLite 后端）

按数据字典，实际后端是 Express + SQLite（端口 3000），Dify 通过工作流封装 SQL / 对话。封装三条主线：

```js
// js/core/difyClient.js
export const fetchSQLWorkflow = async (query) => POST('/v1/workflows/run', {
  inputs: { query },
  response_mode: 'blocking',
  user: uid()
});

export const fetchChatflow = async (query, token, conversationId) =>
  POST('/v1/chat-messages', {
    query,
    conversation_id: conversationId,
    response_mode: 'streaming',
    user: uid()
  }, token);

export const fetchWorkflow = async (workflowName, inputs) =>
  POST('/v1/workflows/run', { inputs: { flow: workflowName, ...inputs } });
```

前端典型调用：

| 业务 | 调用示例 |
|---|---|
| 登录 | `fetchSQLWorkflow(\`查询用户名为${u}密码为${p}\`)` |
| 注册 | `fetchSQLWorkflow(\`创建用户名为${u}密码为${p}的用户\`)` |
| 风险检测 | `fetchWorkflow('RiskPredict_Assess_V1', healthData)` |
| 生成方案 | `fetchWorkflow('LifePlanWorkflow', { riskLevel, type, ... })` |
| 名医对话 | `fetchChatflow(msg, doctor.chat_token, sid)` |
| AI 助手 | `fetchChatflow(msg, GLOBAL_ASSISTANT_TOKEN, sid)` |
| 打卡分析 | `fetchWorkflow('CheckinAnalysisWorkflow', { userId, days: 7 })` |
| 医生列表 | `fetchSQLWorkflow('获取医生列表')` |
| 资讯列表 | `fetchSQLWorkflow('查询3篇文章信息')` |
| 糖尿病类型 | `fetchSQLWorkflow('获取糖尿病类型')` |

统一在 `apiClient.js` 里处理：

- Bearer Token 注入（`localStorage.user`, `localStorage.currentDoctor.chat_token`）
- 15 秒超时 + 失败自动重试 3 次
- 401 → 跳登录；网络异常 → toast
- 流式响应支持（AI 对话打字机效果）

## 六、状态管理（不引框架）

使用 `storageHelper.js` 统一 localStorage：

| Key | 内容 | 用途 |
|---|---|---|
| `user` | `{user_id, username, avatar_url, token}` | 登录态 |
| `userRisk` | 最近一次风险评估结果 | 首页 / 报告页展示 |
| `currentDoctor` | 当前选中医生 | 咨询携带 chat_token |
| `assistantConvId` | AI 助手会话 ID | 保持多轮上下文 |
| `checkinToday` | 当日打卡记录 | 首页/打卡页展示 |
| `newsFavorites` | 收藏列表 | 我的收藏 |

页面间跳转参数用 URL query（如 `news-detail.html?id=12`），跨页共享数据用 localStorage。

## 七、UI 规范

- **主色**：`#22C55E`（健康绿）；辅色 `#0EA5E9`（信息蓝）、`#F97316`（警示橙）、`#F43F5E`（高风险红）
- **中性色**：`#111827` / `#374151` / `#9CA3AF` / `#F3F4F6`
- **字号**：标题 18/16，正文 14，注释 12；行高 1.5
- **圆角**：8 / 12 / 16 三档；卡片阴影 `0 2px 8px rgba(0,0,0,.06)`
- **按钮**：主按钮圆角 24 全宽渐变；次按钮描边
- **图标**：Font Awesome 6 + 少量本地 svg（首页宫格）
- **动效**：页面切换用 CSS transition + `translateX`；Loading 使用 skeleton 骨架屏

## 十一、验收要点

- 375×812 手机外壳在 Chrome/Edge 桌面浏览器中正常居中显示，圆角/阴影效果一致
- Chrome DevTools 手机模式（iPhone 12 Pro）全部页面无横向滚动条
- 首屏加载 ≤ 3 s，AI 助手首字响应 ≤ 3 s
- 断网、Token 失效、模型超时均有明确 toast 提示与降级
- 所有输入具备前端校验（手机号、密码 8–20 位含字母数字、血糖范围）
- localStorage 中不出现明文密码；Token 只在请求头传递
- Playwright 覆盖：登录 → 首页 → 风险预测 → 报告 → 生活方案 → AI 助手 → 打卡的黄金链路
