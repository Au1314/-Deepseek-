## 2. 字段对齐表（SRS ↔ 数据字典）

以数据字典为**开发对齐基准**，SRS 中扩展字段本期通过前端本地扩展或延后。

| SRS 字段 | 数据字典字段 | 对齐结论 |
|---|---|---|
| 手机号 / 邮箱 / 验证码 | `users.username` | 本期用 `username` 直接登录，不做手机号验证码 |
| 密码 | `users.password` | 数据字典明文，前端登录前做 **SHA-256 预哈希** 再传输 |
| 昵称 / 性别 / 年龄 / 身高 / 体重 | `user_risk_info.age/sex/height/weight` | 注册后进入"完善信息"页写入 `user_risk_info` |
| 风险等级"低/中/高" | `user_risk_info.message` | 由前端解析 `message` 或以 Dify 返回结构化字段为准 |
| 是否患病 | `user_risk_info.disease` | 直接使用 |
| 打卡类型（饮食/运动/血糖/用药/体重） | 分散 3 张表 | UI 拆分为 3 入口，见 §5 |
| 咨询/消息表 `t_consultation/t_message` | 数据字典无 | 本期 AI 对话状态仅本地缓存，不落库 |
| 资讯 `t_news` | `articles / article_collections` | 以 `articles` 表为准 |

**冻结日期**：D1 结束前发布《字段对齐表》最终版，之后变更走变更管理流程。

## 6. 环境搭建步骤

### 6.1 本地工具准备

```
Visual Studio Code ≥ 1.92.2
Cline 插件（DeepSeek 接入）
Git（连接 CodeArts 仓库）
Node.js ≥ 18（仅用于 Playwright 和 Live Server）
Chrome / Edge ≥ 90（开发调试）
```

### 6.2 工程初始化

```bash
# 1. 克隆 CodeArts 仓库
git clone <codearts-repo-url> diabetes-assistant-h5
cd diabetes-assistant-h5

# 2. 建立目录骨架（见 §3）
mkdir -p pages components css/pages js/core js/models js/pages img mock tests docs

# 3. 生成占位文件
touch index.html README.md .editorconfig
touch css/{reset,theme,phone-frame,common}.css
touch js/config.js js/core/{apiClient,difyClient,storageHelper,router,formValidator,toast,chartHelper,dateFormatter}.js

# 4. VSCode 打开工程
code .

# 5. 安装 Live Server + Playwright（用于调试与自动化测试）
npm init -y
npm i -D @playwright/test live-server
npx playwright install
```

### 6.3 config.js 模板

```js
export const API_BASE_URL      = 'https://dify.example.com/v1';
export const DIFY_APP_TOKEN    = 'app-xxxxxxxxxxxxxxxx';   // 通过后端代理注入，禁止硬编码进仓
export const REQUEST_TIMEOUT   = 15_000;
export const REQUEST_RETRY     = 3;
export const APP_VERSION       = '1.0.0';
```

**API Key 严禁提交到仓库**：加入 `.gitignore`，通过 CodeArts 流水线变量注入。

## 8. 安全与合规基线（P2 修正）

1. **密码传输**：登录/注册前端 SHA-256 预哈希 → 后端二次加盐哈希落库。
2. **Prompt 注入防护**：所有拼入 `fetchSQLWorkflow` 的用户输入必须走 `escapePromptInput()` 白名单校验（仅允许字母数字与常见汉字）。
3. **Token 存储**：`user.token` 和 `chat_token` 存 `sessionStorage`；退出登录/关闭 tab 自动清除。
4. **HTTPS**：Nginx 强制 HTTPS，禁止明文；启用 HSTS。
5. **CSP**：`Content-Security-Policy: default-src 'self'; script-src 'self' cdn.jsdelivr.net; connect-src 'self' https://dify.example.com`。
6. **数据最小化**：仅采集糖尿病风险评估所需字段，明文提示用户数据用途。

## 9. 移动端适配踩坑清单

| 问题 | 解决方案 |
|---|---|
| iOS Safari `100vh` 含地址栏 | 用 `100dvh` 或 JS 动态计算 `--vh` CSS 变量 |
| 软键盘弹起遮挡输入框 | 输入框 focus 时监听 `resize`，滚动到视口内 |
| 底部安全区（Home Bar） | TabBar 加 `padding-bottom: env(safe-area-inset-bottom)` |
| 顶部刘海 | 页面顶部 `padding-top: env(safe-area-inset-top)` |
| 双击缩放 | `<meta name="viewport" ... user-scalable=no>` |
| 长辈模式 | 通过 `<html data-font="large">` 切换根字号 `18px` |
| PC 手机壳右侧留白 | 放"演示说明面板 + 扫码到手机" |

## 11. DevOps 与协作

### 11.1 代码仓与分支

- 主仓：CodeArts Git，主分支 `main` 保护，禁止直推。
- 特性分支：`feat/D{day}-{module}`，例 `feat/D4-risk-prediction`。
- Bug 分支：`fix/{issue-id}-{desc}`。
- 每日 17:00 前提交 PR，17:30 团队 code review，18:00 合入 main。

### 11.2 CodeArts 任务卡

- 每张任务卡关联 SRS FR 编号；关闭前必须附上：代码 PR 链接 + 自测记录 + 需求跟踪矩阵勾选状态。

### 11.3 AI 编程约定

- 使用 Cline + DeepSeek-V3 生成代码，**Prompt 必须包含**："遵循详细设计 §1 命名规约"、"输出纯 ES6+ 无框架代码"、"包含错误处理"。
- AI 生成代码必须走一次人肉 review，重点检查：命名、错误处理、Prompt 注入、日志、可读性。
- 测试脚本用 DeepSeek-R1 根据用例生成 Playwright 脚本。

### 11.4 前后端联调时间线

```
D1 ─ 字段对齐冻结 ──┐
D2 ─ 登录接口       │ Dify SQL Workflow 完成
D4 ─ 风险预测接口   │ Dify RiskPredict_Assess_V1 完成
D5 ─ 生活方案接口   │ Dify LifePlanWorkflow 完成
D6 ─ 医生 Chatflow  │
D7 ─ AI 助手 Agent  │
D8 ─ 打卡分析工作流 ┘
```

前端 D1-D3 期间用 `mock/` 假数据独立开发；D4 起进入并行联调期。

## 13. UI 规范摘要

- **主色**：`#22C55E`（健康绿）
- **辅色**：`#0EA5E9`（信息蓝）/ `#F97316`（警示橙）/ `#F43F5E`（高风险红）

- **圆角**：8 / 12 / 16 三档
- **卡片阴影**：`0 2px 8px rgba(0,0,0,.06)`
- **主按钮**：全宽、圆角 24、绿色渐变
